# AI reviewer (F1)

- The reviewer asks the model for JSON `{ comments: [{ quote, category, severity, rationale, question? }] }` under `BASE_SYSTEM` plus a hard ban on replacement prose (`src/lib/ai/reviewer.ts`); the parser drops quotes not in the passage, categories outside the active rubric, duplicates, anything with a pastable sentence of 12+ words, and caps a section at 8 comments ordered by severity.
- Anchoring (`src/lib/ai/anchor.ts`, AnchoredAI recipe): exact match → normalised match (case, whitespace, quotes, dashes) → repeated matches disambiguated by widening the context window word → sentence → paragraph → fuzzy sentence (token Jaccard ≥ 0.6) → fuzzy paragraph; otherwise the comment is dropped. The server anchors inside the plain text it reviewed; the panel maps those offsets to ProseMirror positions by walking text nodes, re-locates on the live document if it changed meanwhile, and applies the same `commentMark` the Comments panel uses before posting to `/api/theses/[id]/comments` with `source: "ai"`.
- After every edit the panel recomputes `anchorStatusFor(markedText, quote)`: `live`, `stale` ("Text changed", similarity below 0.6) or `orphaned` ("Anchor lost"); comments never move silently.
- Demo mode (no provider key): `demoReview` picks 3–5 sentences by textual cues (unsupported claim words, numbers without a reference, inference connectors, 45+ word sentences, unquantified methods, paragraph-opening transitions) and attaches rubric rationales and questions. Deterministic for the same text and rubric; the panel labels it as demo.
- Rubric: six criteria with weights 0–3 (`DEFAULT_RUBRIC`), overridden per university in `Policy.reviewRubric` via `GET/PUT /api/policies/rubric` and the "Reviewer rubric" card in Admin → AI policies.
- Limitations: `reviewRunId`, `question` and `anchorStatus` reach the comment through a second `PATCH /api/ai/reviewer` call because the generic comments route only stores `source/category/severity`; "Share with advisor" only sends a notification (no `sharedAt` on `ReviewRun`), so the "Shared" label is a per-browser `localStorage` marker; a `ReviewRun` is created even when zero comments survive validation, so cost is always logged; documents above 40k characters must be reviewed by section.
